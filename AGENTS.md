# Proyecto

Este proyecto corresponde al sitio web de "Bordados Danny".

# Tecnologías

- HTML
- CSS
- JavaScript
- GitHub
- Cloudflare Pages

# Reglas generales

- Mantener el sitio sencillo, rápido y fácil de mantener.
- No agregar frameworks como React, Vue, Angular u otros salvo que el usuario lo solicite explícitamente.
- Mantener separados los archivos `index.html`, `styles.css` y `script.js`.
- No agregar dependencias innecesarias.
- No eliminar contenido existente sin autorización.
- No modificar enlaces de WhatsApp, correo, teléfono o datos de contacto sin autorización.
- Mantener compatibilidad con Cloudflare Pages.
- Mantener buena ortografía en español.
- Antes de terminar un cambio, revisar que no existan errores de sintaxis.
- Mantener finales de línea CRLF en Windows.

# Diseño responsive

- Todo el diseño debe adaptarse correctamente a dispositivos móviles, tablets y computadoras.
- Priorizar una buena experiencia en teléfonos móviles.
- Ningún elemento debe salirse del ancho de la pantalla.
- Evitar desplazamiento horizontal no intencional.
- Evitar anchos fijos que rompan el diseño en pantallas pequeñas.
- Usar porcentajes, `rem`, `clamp()`, `min()`, `max()`, flexbox, grid y media queries cuando sea conveniente.
- Las imágenes deben adaptarse al tamaño disponible.
- Los formularios deben poder utilizarse cómodamente desde dispositivos móviles.
- Los botones y enlaces deben tener un tamaño adecuado para pantallas táctiles.
- Los menús deben funcionar correctamente en móvil.
- El texto debe mantenerse legible en pantallas pequeñas.
- Antes de finalizar cualquier modificación visual, revisar el comportamiento aproximado en anchos de:
  - 320 px
  - 375 px
  - 768 px
  - 1024 px
  - escritorio

# Forma de trabajar

- Antes de modificar archivos, revisar la estructura existente del proyecto.
- Reutilizar estilos y componentes existentes cuando sea posible.
- Evitar duplicar código CSS o JavaScript.
- Mantener nombres de clases y funciones comprensibles.
- Si una petición puede afectar contenido existente de forma importante, conservarlo salvo que el usuario solicite reemplazarlo.
- No hacer `git commit` ni `git push` automáticamente salvo que el usuario lo solicite explícitamente.
